## Authority and governance boundaries

Clear separation of ownership is mandatory across all repository layers:

1. `/knowledge` owns audit-domain semantics:
   - Authoritative for the 100-check audit catalog ([`02-audit-check-catalog.md`](../knowledge/02-audit-check-catalog.md)), 47 frozen executable atomic rules ([`07-v1-atomic-rule-manifest.md`](../knowledge/07-v1-atomic-rule-manifest.md)), rule engine evaluation contracts ([`03-rule-engine-spec.md`](../knowledge/03-rule-engine-spec.md)), AI Search / GEO guardrails ([`04-ai-search-geo.md`](../knowledge/04-ai-search-geo.md)), frozen system architecture ([`08-system-architecture.md`](../knowledge/08-system-architecture.md)), logical data model ([`09-data-model.md`](../knowledge/09-data-model.md)), and phased implementation sequencing ([`10-implementation-plan.md`](../knowledge/10-implementation-plan.md)).
   - Domain semantics, status definitions (`PASS`, `WARNING`, `FAIL`, `UNKNOWN`, `MANUAL_REVIEW`, `NOT_APPLICABLE`), severity levels (P0–P3), and evidence snapshot contracts must not be invented outside `/knowledge`.

2. `/docs` owns project-specific migration decisions:
   - Authoritative for standalone extraction strategy, module classification, and package organization as documented in [`sitecrawl-standalone-migration-map.md`](../docs/sitecrawl-standalone-migration-map.md).

3. `.ai-dev-system` owns agent workflow:
   - Authoritative for how agents explore context, specify, plan, implement, verify, and converge changes ([`INDEX.md`](docs/INDEX.md), [`default.md`](core/constitution/default.md)).
   - AI Dev System must not own or duplicate SEO/GEO audit domain policy.

4. Existing SiteCrawl source and runtime behavior is authoritative for currently implemented crawler behavior:
   - Proven crawling mechanisms in `go/engine/` and `go/storage/` (URL normalization, BFS frontier, host politeness, robots/sitemap parsing, HTTP acquisition, HTML extraction, link graph building, rendering hooks) represent working acquisition behavior and must not be rewritten from scratch.

5. Legacy audit code is compatibility behavior only, NOT Audit V1 authority:
   - [`issues.go`](../go/engine/issues.go) (legacy issue taxonomy, 55 kebab-case issue codes), legacy indexability heuristics (`indexabilityOf`), legacy severity assignments (`critical`, `warning`, etc.), and post-crawl issue writes in [`finalize.go`](../go/storage/finalize.go) are legacy reference/compatibility behavior only.
   - Legacy issues and heuristics must not be treated as authority for Audit V1 verdicts or mapped 1:1 to `AR-*` rules.

## Risks and unknowns

- Platform dependency coupling: SiteCrawl files in `go/storage/`, `go/pagespeed/`, and `go/app-glue/` depend on 1Scout platform packages (`core/*`). Extraction without breaking existing crawl logic requires careful stubbing or standalone replacement.
- Risk of premature audit implementation: Attempting to implement `AR-*` rules before standalone crawler parity is reached risks compounding extraction bugs with domain logic defects.
- Risk of divergent refactoring: Over-engineering the crawler package structure during extraction could make future reintegration into 1Scout prohibitively expensive.

## Decisions

- Baseline preservation: Tag `sitecrawl-pre-audit-v1` is immutable and marks the reference state (`82c610d433203374473e1ea76edf4e6c165a3161`) before any standalone migration edits.
- Phased execution: Standalone extraction and buildability must precede Audit V1 domain implementation.
- Checkpoint sequencing: Checkpoint A1 (Buildability Inventory), Checkpoint A2 (Scoped Go Module Bootstrap), Coordinated Checkpoint A3/A4 (Standalone SiteCrawl Engine & Platform Primitives), and Checkpoint A5 (Standalone End-to-End SiteCrawl) are completed. Checkpoint A2 established root `go.mod` (`github.com/truthrive/technical-seo-audit`, `go 1.22`). Coordinated Checkpoint A3/A4 reconstructed `internal/sitecrawl/` and `internal/platform/standalone/` without 1Scout dependencies. Checkpoint A5 proved end-to-end crawling, SQLite persistence, process reopen, and context cancellation. Next milestone is Checkpoint A6 (regression parity + full module gate).
- Package consolidation strategy: Prefer consolidating Go files into a unified `internal/sitecrawl/` package during standalone extraction to preserve package-private access rather than fracturing into multiple subpackages prematurely.
- Evidence adapter pattern: The boundary between SiteCrawl acquisition and the Audit V1 engine will be an Evidence Adapter converting crawl observations into normalized evidence snapshots, preserving crawler stability.
- Domain authority: All audit logic and rule definitions are governed exclusively by `/knowledge`.
